# GitHub Sync (Mobile) для Obsidian

Синхронизация хранилища Obsidian с репозиторием GitHub, которая работает на **iOS** и Android.
Плагин не требует `git` и Node.js: он ходит в GitHub REST API (Git Data API) через `requestUrl`.

- **Pull**: скачивает изменения с GitHub и автоматически сливает непересекающиеся правки в одном файле.
- **Commit & Push**: показывает список изменений, даёт отредактировать сообщение и делает один коммит в ветку.
- **Sync**: Pull, затем Push.
- **Конфликты**: удобное окно для телефона. Для каждого конфликтного фрагмента видны «Моё» и «GitHub», есть кнопки «Моё / GitHub / Оба / Править». Можно выбрать версию для всего файла сразу или записать маркеры `<<<<<<< ======= >>>>>>>` и исправить их в редакторе.
- **Автосинхронизация** (настраивается): Pull или Sync при запуске, Sync каждые N минут.

## Как это работает

Плагин хранит на устройстве «базу», то есть SHA файлов на момент последней синхронизации, и сравнивает три версии: базу, локальную и удалённую.

| Локально | GitHub | Что происходит |
|---|---|---|
| не менялось | изменилось | файл скачивается или удаляется |
| изменилось | не менялось | файл попадает в следующий push |
| изменилось | изменилось | трёхстороннее слияние (diff3); если правки пересекаются, это конфликт |

Push создаёт blob'ы, дерево и коммит и переносит ветку только fast-forward'ом (`force: false`), поэтому чужие коммиты не затираются.
Пока не разрешены все конфликты, push заблокирован.

Локально папка `.git` не создаётся. История живёт на GitHub.

## Установка

1. Соберите плагин: `npm install && npm run build`. Получатся `main.js`, `manifest.json` и `styles.css`.
2. Скопируйте эти три файла в `<хранилище>/.obsidian/plugins/github-sync-mobile/`.
   - **iOS**: если хранилище лежит в iCloud, скопируйте файлы с Mac в папку хранилища в iCloud Drive. Если нет, используйте приложение «Файлы» (*На iPhone → Obsidian → <хранилище> → .obsidian/plugins*).
   - Ещё вариант: опубликовать репозиторий плагина на GitHub и установить через плагин **BRAT**.
3. Obsidian → Настройки → Сторонние плагины → включите **GitHub Sync (Mobile)**.

## Настройка

1. Создайте репозиторий на GitHub (можно пустой и приватный).
2. Создайте **fine-grained token**: GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens.
   - *Repository access*: только нужный репозиторий.
   - *Permissions → Contents*: **Read and write**.
3. В настройках плагина укажите токен, владельца, имя репозитория и ветку, затем нажмите «Проверить».
4. Выполните **Sync** (иконка ⟳ на боковой ленте или в палитре команд).
   - Пустой репозиторий: всё хранилище отправится в первый коммит.
   - Пустое хранилище: всё скачается с GitHub.
   - Если файлы есть и там и там: одинаковые останутся как есть, различающиеся станут конфликтами.

> Совет для iOS: добавьте команды *Sync* и *Resolve conflicts* на панель инструментов (Настройки → Мобильные → Панель инструментов).

## Команды

| Команда | Что делает |
|---|---|
| Sync (pull + push) | Pull, затем push с автоматическим сообщением |
| Pull | Только скачать изменения |
| Commit & Push | Показать изменения, спросить сообщение, затем синхронизировать |
| Show changes | Список локальных изменений и конфликтов |
| Resolve conflicts | Открыть список конфликтов |
| Mark file as resolved | Для файла с маркерами: пометить конфликт решённым (маркеров в файле быть не должно) |

## Что не синхронизируется

Это не настраивается:
- `.git/`, `.trash/`, `.DS_Store`
- `.obsidian/workspace*.json` и `.obsidian/cache`
- `data.json` и `sync-state.json` этого плагина (в них **токен** и состояние устройства)

Настраивается:
- папка `.obsidian` целиком (по умолчанию синхронизируется);
- свои шаблоны в стиле `.gitignore`.

Файлы больше 50 МБ пропускаются (ограничение GitHub API).

## Ограничения

- Только GitHub (github.com).
- Очень большие репозитории (более 100 000 файлов): GitHub отдаёт усечённое дерево, и плагин сообщит об ошибке.
- Первая синхронизация большого хранилища делает по одному запросу на файл. Лимит GitHub — 5000 запросов в час.
- Символические ссылки и подмодули в репозитории игнорируются.

## Разработка

```bash
npm install
npm run dev     # сборка с watch
npm run build   # tsc + production-сборка
npm test        # vitest: hash, ignore, merge, движок синхронизации на фейковом GitHub
```

Структура:
- `src/engine.ts`: логика pull/push/конфликтов, без зависимостей от Obsidian;
- `src/github.ts`: клиент GitHub API;
- `src/vaultio.ts`: доступ к файлам хранилища;
- `src/ui/`: модальные окна.
